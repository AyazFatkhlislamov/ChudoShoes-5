# Чудо Обувь — система заказа обуви

Настольное приложение (WPF, C#, .NET Framework 4.7.2, Entity Framework 6) для торговой компании «Чудо Обувь». Клиенты выбирают обувь из каталога и оформляют заказ, менеджеры и администраторы работают со списком заказов. База данных — Microsoft SQL Server (`ChudoShoesFatkhlislamovDB`).

## Запуск

1. Восстановить базу из скрипта `ChudoShoesDB_final.sql` (структура и данные) в SQL Server.
2. В файле `App.config` в строке подключения заменить `data source=ASUStuf\ISPO` на имя своего сервера.
3. Открыть `ChudoShoes.sln` в Visual Studio, выполнить «Пересобрать решение» и запустить.

## Роли и вход

Вход выполняется только по логину из таблицы пользователей, пароль не нужен. Также доступен вход гостем. После входа ФИО и роль пользователя отображаются в правом верхнем углу страницы.

| Роль | Пример логина | Возможности |
| --- | --- | --- |
| Неавторизованный (гость) | — | Просмотр каталога и карточки товара без поиска, фильтрации и сортировки. Заказ оформить нельзя |
| Авторизованный клиент | asidorova | Каталог с поиском, фильтрацией и сортировкой, оформление заказа |
| Менеджер | papetrov | То же, что у клиента, плюс список заказов, состав заказа, создание заказа для клиента и удаление заказа |
| Администратор | isivanov | То же, что у менеджера, плюс редактирование заказа: изменение даты, добавление и удаление позиций |

## Каталог товаров

- Для каждой модели выводятся изображение, категория, наименование, производство, состав, цена со скидкой и количество пар суммарно по всем размерам: «много» при количестве больше 5, «мало» при 5 и меньше.
- Модели, у которых суммарно доступно 3 пары и меньше, подсвечиваются цветом `#FF8080`.
- Если изображения нет, подставляется `picture.png`.
- Скидка 25% применяется к моделям, по которым не было заказов в календарном месяце, предыдущем относительно даты расчёта. Датой расчёта считается самая поздняя дата заказа в базе. Исходная цена выводится зачёркнутой.
- Поиск по наименованию и описанию, фильтр по категории и сортировка по цене работают одновременно в реальном времени. Выбранная сортировка сохраняется при поиске и фильтрации.
- Одинарный клик по модели открывает карточку товара.

## Карточка товара и оформление заказа

- Карточка загружает данные из базы: изображение, наименование, категория и подкатегория, производство, состав, описание, размерный ряд, доступные размеры, цена.
- Выбрать можно только размер, который есть в наличии. Количество принимает только цифры и не может превышать остаток с учётом уже добавленных в заказ позиций.
- После добавления позиции можно перейти к заказу или продолжить выбор в каталоге.
- В корзине количество меняется кнопками «+» и «−», позиции удаляются, итоговая сумма пересчитывается.
- Перед оформлением показывается подтверждение с клиентом, количеством и суммой. При оформлении фиксируется дата, остатки на складе уменьшаются, каталог обновляется.
- Отказаться от заказа можно на любом этапе, перед этим выводится предупреждение.

## Управление заказами (менеджер и администратор)

- Список заказов с номером, датой, ФИО клиента и суммой. Выбрав заказ, можно увидеть его состав: модель, производство, размер, количество, цена за единицу и сумма по позиции, а также итог по заказу.
- Новый заказ создаётся через каталог с выбором клиента. Заказ можно удалить, остатки при этом возвращаются на склад.
- Только администратор может изменить дату заказа, добавить позицию (поиск модели по наименованию, выбор размера и количества) и удалить позицию. Если удалена последняя позиция, заказ удаляется. После любых изменений список обновляется.

## Оформление и обработка ошибок

- Шрифт Calibri, фон белый, дополнительный фон `#D2F6E7`, акцент на целевых действиях `#70B2AF`. Логотип в шапке главного окна, на каждой странице есть заголовок, кнопка «Назад» в шапке.
- Предупреждения, ошибки, подтверждения и информационные сообщения выводятся окнами с заголовком и пиктограммой. Ошибки работы с базой данных перехватываются, приложение не завершается аварийно.

## База данных

Таблицы: `Category`, `Subcategory`, `Manufacturer`, `Product`, `Size`, `StockItem` (остаток по сочетанию модели и размера), `Role`, `User`, `Order`, `OrderItem`. Все связи заданы внешними ключами, включая `OrderItem → StockItem`.
